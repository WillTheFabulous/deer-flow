# Product Context
[Last Updated: 2026-11-02]

## 为什么做

- 在 IM 里直接用自托管 agent；复杂编码任务交给角色流水线 + Cursor CLI，人在飞书里看进度、做决策。
- POD 毛毯（Temu 店铺）设计：把爆款参考图拆成 14 维可控变量，在人批准的系列范围内批量产出原创、可区分、可质检的印花候选，人只在审批门做决定（`pod-blanket` 人设）。

## pod-blanket 工作流

- 入口：飞书 `/agent pod-blanket`（或 `/pod-blanket <任务>`）、Web 选该人设；后台由网关定时器每 10 分钟巡检一次（连续运行窗口内才自动出图），每天 21:00 发日报（2026-10-27 起换成每天 10:00 / 15:00 / 21:00 的状态总结 + 有待办时每小时的待办提醒，见下「通知」）。一页使用说明：`skills/public/pod-blanket/references/usage.md`。
- **飞书 POD 工作台**（单聊发 `/pod` 或点菜单 POD）：
  - **内容：** 顶部「进度」（后台正在做什么、批次完成数）和「下一步」（现在卡在哪、该点哪个按钮）；下面是状态汇总、待审项（带缩略图；每张选款先放这个任务的原图、再放候选，写着裂变方向（标题、改哪几处、不变）和出图模型、文生图 / 图生图，2026-10-14 起）、任务列表、最近动态、已选款（可发原图文件）、日报、巡检、暂停 / 恢复、开启 / 停止连续运行。
  - **操作：** 挑选裂变方向（2026-10-22 起方向自动全部确认、直接出图，挑选卡只在自动确认没成功或旧批次上用；策划按钮写「…并出图」；挑选卡是勾选清单，分「小变化」「大变化」两段：每行一个方向，写着标题、改哪几处「字段：原来 → 改成」，大变化另写不变的部分；卡片开头写这张图哪些维度不适用、哪些字段判定不能变；勾完点一次「按勾选的方向出图」，或「换一批」；清单上面有「全选 / 全不选」（2026-10-19）；勾选框要飞书 V7.9+）、选款、策划新一轮方向、开始出图、连续运行开关直接点按钮，不经过大模型；长任务转后台，做完发完成卡片（失败发红卡）。
  - **任务列表**（2026-10-14）：一张参考图一个任务，按「待你处理 → 进行中 → 已完成 → 其他」排，每个任务写着缩略图、五步进度（拆解 / 策划 / 挑选 / 出图出完几个方向 / 选款待选·选中张数）、现在在做什么和该点的按钮（去挑选 / 开始出图 / 去选款 / 看明细）。选中的方向全部出完图就算「已完成」（选款可以之后审），在列表里写一句这次想要的方向（可不填）点「继续裂变」就再策划一轮，接着挑选、出图。POD 对话里问「各个任务到哪一步了」也行。
  - **任务名字**（2026-10-20）：拆解开始的同时，模型看参考图写一个 4–8 字的描述，接上上传那天的月日作为任务名字（如「动物三伙伴水彩 1008」）；任务列表、任务明细、挑选卡、只关于这张图的卡片标题和候选表表名都写成「S01 名字」，人设汇报也带名字，编号照留、命令照旧用编号。名字只起一次；在 POD 对话说「S01 改名叫……」（日期不变）或「S01 重新起个名字」可以改，候选表表名跟着改。
  - **任务明细**（原方向记录，2026-10-14）：一张参考图一张卡，顶部是进度，按批次从新到旧列出做过和提过的方向，每个方向细到哪一步（已出完 n 张 · 待选 a · 选中 b / 出图中 4/6 / 质检中 / 排队 / 待出图 / 没选），底部可写一句这次想要的方向（可不填）再按可变字段策划一轮；做过、在出、没选的方向都不会再提。入口：任务列表的「看明细」、挑选卡、「出图一轮结束」卡片的「再策划新方向」；POD 对话里说「F01 做过哪些方向」「F01 再出一轮，往海洋动物方向」也行。
  - **选款表**（2026-10-15）：选款里点了「选中」的图自动同步进飞书多维表格「POD 毛毯选款表」，一行一张：缩略图、原图（参考图缩略图）、方向、改了什么、不变、模型、出图方式、批次、选中人、下载原图（OSS 签名链接，90 天、自动续签，不占飞书空间）；改判成不要的行删掉。入口：工作台固定按钮「选款表」、「已选款」卡片的「打开选款表」、建表时发的卡片。
  - **候选表四个视图**（2026-10-30 用户定，取代 10-29 的「看图跟着选款进度」）：从左到右是表格「全部」（所有行都看得到）、画册「全部画册」（所有有图的原图，不放套图）、画册「已选中」（所有已经选中的原图，卡片上有店铺勾和货号）、画册「待选」（还没选过的图，链接打开它）。用户两次以为「原图后面的店铺勾不见了」，其实是选中后离开了原来的「待选」表格视图，勾都在。
  - **每周选款表**（2026-10-29）：知识库根目录一本锁住的「POD 选款表模板（勿改）」（编辑者只读，「看图」封面效果在里面设一次），每周从它复制一本「POD 选款表 W44（10.26–11.01）」：每天一个文件夹「10-26 周一」，放那天上传的任务的候选表、「10-26 选中的款」和「10-26 已归档」子文件夹；「已上架的款」每本一张。任务按上传日期归到那一天，以后继续裂变、补选也在那天；10-25 及以前的任务留在旧的「POD 毛毯选款表」。工作台「选款表」打开这一周的（今天的「选中的款」）。人自己在旧表里加的「使用情况」「下载情况」不带进新表（下载由「下载确认」管）。
  - **候选表选款**（2026-10-20）：每个任务（参考图）一张飞书多维表格「S01 候选」，进了选款的图都在里面（缩略图、「选中」勾选框、「选款结果」、原图下载链接）；在表里打钩，再在任务列表点「选款完成」（或 POD 对话说「S01 选款完成」）：勾上的算选中、没勾的算不要，卡片上逐张定过的以卡片为准；做完发卡片，选中的款接着出套图（同日起不再打压缩包下载）。卡片里的逐张选款和修改照旧，结果同步回表里。2026-10-22 起：选款只看「选中」，原来的「状态」改名「选款结果」（程序写的结论、手改不算），两列表头都有说明；进选款不到 10 分钟、或验收时才补进表的新图，没勾就留到下次验收，勾了照常算选中。2026-10-23 起不用回聊天框：每张候选表最底下一行「▶ 选款完成」，在它的「选中」打勾，几秒内后台验收整张表（这一行的「备注」写验收中 / 上次结果，照样发卡片）；验收扣掉这个任务待审积压里的选款，被积压挡住的出图当场接着出。这一行下面每个选中的款一行「套图 · IMG…」，写套图状态、场景图张数和「下载套图」，出完自动填上；有新图进表时这一组整体回到最底下。
  - **素材名字**（2026-10-20）：候选表和选款表的「素材」列、缩略图附件、下载下来的原图、「发原图」收到的文件、套图压缩包里的设计图都叫「编号_方向短语」（如「IMG00327_羊驼河马小熊猫」，短语就是「方向」列那句），一看文件名就知道是哪个方向的图。
  - **飞书里的名字**（2026-10-21）：卡片和 POD 对话里提到编号都带上和表格一样的名字：任务「S01 动物三伙伴水彩 1008」，批次 / 系列「S01 … · B008」，图片「IMG00325_羊驼河马小熊猫」，方向「V0075 羊驼河马小熊猫」。选款卡的标题和图下的字、工作台进度和下一步、最近动态、已选款、修改 / 失败 / 出图一轮结束 / 套图卡片、人设汇报都这样写，能拿卡片上的名字去候选表里对；说编号仍然能操作。
  - **可改的主体**（2026-10-25）：画面描述里另列可改的主体——一个角色、一组星星、一圈花边、几处相似点缀（成组的算一个），多个角色时既有「全部角色」也有显眼的单只，各标大 / 中 / 小；拆解完成和画面描述卡片写「可改的主体：…」。小变化改两处、三处组合改三处，一处 = 一个主体上的一个字段（整体配色、画法算整幅的一处）：太小的不单独改，同一个主体上改两处要它是大主体，整幅最多一处；卡片和候选表「改了什么」写「主体·字段：原来 → 改成」。分得不对在 POD 对话说「S0x 的星星和月亮算一组」重写；POD 对话说「F0x 下一轮会怎么改」可以先预览、不花钱。2026-10-26（字段字典 0.5）：游戏手柄、月亮这类没有脸的主角单独算「物件」（能换成同主题的另一种物件、改轮廓、加笑脸、戴配件），装饰群也能改轮廓、加笑脸；小变化不改绘制技法，能只给一个主体换色（单元配色）或换格纹 / 波点 / 碎花这类表面纹样；三处组合还会改动作、互动、陪衬、头身这类构图不动时改不了的地方，布局跟着调；有文字的图按文案库写英文短句和示例名字。
  - **小变化以换主体为主、二次大变化、只用 sunburst**（2026-10-27）：用户嫌小变化太多、图又很像（配色、装饰变化不明显，主体变化最明显），要小变化里大量是主体变化，另一部分大变化在已经换了主体的小变化上再做。现在生图只用 gpt-2.5-sunburst（小变化每个方向 1 张、大变化 2 张），所以每轮多出方向：小变化 30 个，其中八成至少一处「换主体」（整个换成同题材的另一种动物 / 角色 / 物件，模型先列一份互不相同的新主体清单、一个方向分一个；图上没有能换的主体时照旧），大变化 24 个（单字段大改 12 + 三处组合 12，同一个大改字段一轮最多两次）；这一批小变化出完后程序自动挑 16 个换了主体的小变化，拿它们出的图当底图各做一个单字段大改（**二次大变化**：主题 / 构图 / 画法换一个，图生图以这张小变化图为输入、新主体长相保持），也自动确认、直接出图。选款卡第一张放底图，任务明细的批次写「二次大变化（底图来自 B…）」，挑选卡 / 任务明细方向太多时卡片只列标题或前几行。POD 对话说「B0xx 的换主体小变化再出一轮大变化」可以手动做（先预览挑哪些底图）。一张新图一轮约 70 个方向、110 张图。
  - **去掉构图判断、设计建议不锁、动态字段与换画法配额**（2026-10-27 夜）：用户审查了全部限制，本意是尽量有丰富的变化。现在拆解只看一个字段在这张图上能不能改出看得见的变化（不再因为「会挤动构图」判不能变）；系列规则只按用户和印制要求锁字段，模型自己的设计建议不再锁死主题、季节、叙事；动作姿态、朝向视线、距离互动、承托依附、陪衬角色这类动态字段也能单独做大改（可以挪位置、改布局），大变化按配额出：单字段大改 12 个里动态 4、换画法 4、主题 / 构图 4，三处组合一半含动态，二次大变化约四成换画法；换画法的方向由程序各分一种不重复的画法（避开原图那种和做过的）。其余方向的画风统一照旧。老系列还没按新规则重拆（用户说先不做），小变化仍按旧判定。
  - **没选原因**（2026-10-26）：候选表多一列「没选原因」（多选、选填：变化太小 / 变化太大不像原图 / 画错变形 / 画风不统一 / 配色不好看 / 不好卖 / 和别的款重复 / 其他），在没勾的行上点几下；选款完成时自动读回来，批次反馈按方向类型、字段、主体归纳，POD 对话问「没选的都是什么原因」看汇总。之前建的表这一列在最后。
  - **画面描述与画风统一**（2026-10-21）：拆解之后模型把参考图完整反推一遍（画风、配色、每个主体的物种 / 颜色斑纹 / 表情 / 动作 / 位置、环境、构图、画风统一规则），之后策划方向、写出图指令和质检都照它写：文生图把没改的主体和画风写全，换场景 / 背景 / 加元素时新内容用参考图同一套画法（不加写实光照、薄雾），只有改配色、改绘制技法的方向才整幅换画风。POD 对话说「S01 的画面描述给我看看」可以看，认错了就说更正、只重写描述。某个方向的图和原图脱钩或画风打架时说「<方向>按新规则重出」：旧图撤出选款，按画面描述重新写指令、重新出图（再花一轮费用，选中的款不能作废）。
  - **套图**（2026-10-20）：选中的款交给 mooya 的图案管线（Pattern Showcase 毛毯）出一套白底图 + 约 16 张场景图，提示词和流程跟着 mooya 更新；选款完成后自动出（同时 2 款，一款约 15–25 分钟），之后逐张补选的款在任务列表点「出套图（n 款）」。每个任务出完发「套图出完」卡片，选款表「选中的款」写入套图状态、张数和「下载套图」压缩包（设计图 + 白底图 + 场景图；2026-10-29 起不放场景图缩略图）；任务列表多一步「套图 d/n」。mooya 停在要人看的一步（如白底图门控）时显示「等人工」，去 mooya 网页处理后自动接着拉；已出过的重出要在 POD 对话里明确说（再花一套费用）。
  - **套图交付包**（2026-10-23）：每个任务的每个裂变批次打一个交付包（每款一个文件夹：设计图 + 白底图 + 场景图，下载名「S07_任务名_B010_套图交付包.zip」）；批次里的套图出完就打（停在 mooya 等人工的款不挡，出完补进去重打），之后补选 / 重出的款出完会重打、链接换新，继续裂变出的新批次各有各的包。下载入口：任务列表每个任务的第一行与最前面的「交付包 B…」按钮（新批次在前，最多 3 批）、候选表「套图交付包」列（新建的表在第 2 列，之前的表在最后一列、拖到前面一次就行）、任务明细的批次标题、「套图出完」卡片；POD 对话问「交付包在哪」也给链接。
  - **候选表排法、预留行、先出套图、交付包已下载**（2026-10-26）：候选表按程序算好的隐藏「排序」列排，表顶依次是「▶ 选中的先出套图」「▶ 选款完成」两个按钮行、还没标已下载的交付包行和它们的套图行，下面是候选图（新批次在前），标了已下载的交付包行连同套图行沉到最底。方向一确认就按出图张数预留「未生成」的行，出图后原行补图，没出图是「没出成」，这两种行打勾不算。2026-10-30 下午起（用户要求）：表顶只留「▶ 选款完成」，随时能点，是标记——勾上的选中、出了图没勾的标没选中、表名改【选款完成】，之后再出新图是【有新图】，选了还没点是【已选N款】；勾店铺 5 分钟犹豫期后这一款自己走套图和上架；「选中的先出套图」那一行删了（对话里说照样能用）；选中的款都上架完，表挪进「已归档」。下载了交付包点「B… 已下载」（或在交付包行打勾、对话里说），任务从「套图完成」到「套图已下载」，标错能撤销。

## 使用入口

- Web：`http://<宿主机>:2026`（dev 栈要设 `BIND_HOST=0.0.0.0` 并把局域网 IP 加进 `DEER_FLOW_DEV_ALLOWED_ORIGINS` 才能局域网访问）；首次 `/setup` 建管理员。**2026-10-31 起前端默认不启动**（腾内存给套图并发），日常只用飞书；要网页时管理员临时起前端（`--profile web`），用完再停。
- 飞书：单聊，或群里 @机器人。渠道全是出站连接，不需要公网 IP。使用前要把管理员给的 `/connect` 连接码发到单聊；未绑定只会收到绑定提示。
- 团队成员接入（2026-10-31 起不走网页、自助注册已关）：飞书应用「可用范围」包含该成员 → 管理员跑 `scripts/fork/onboard_member.py add --email <邮箱>`（建账号、不设密码，打印一次性 `/connect <码>`，10 分钟内有效）→ 成员在机器人单聊发这句。绑定按「人 + 会话」记，群里要单独再绑一次：管理员跑 `code --email` 再拿一个码，成员在群里 @机器人 发。

## 飞书交互

- **命令**：`/new` `/sessions` `/repo` `/agent` `/model` `/models` `/memory` `/status` `/goal` `/bootstrap` `/help`，以及 `/<skill-name> <任务>`。
- **卡片**：裸命令 `/repo` `/agent` `/sessions` `/memory` `/model(s)` 回复交互卡片；带参数时走文本命令。
- **人设**：切换人设 = 以该人设开启新会话（上游把 agent 钉在线程上，同一会话中途不换人设）；`/new` 沿用当前人设。
- **工作目录**：选定后每条消息前注入目录上下文；候选目录来自 `sandbox.mounts` 的各项目根（`/mnt/projects`、`/mnt/prod_data`）的直接子目录。
- **多会话**：`/sessions` 列表 / 切换 / 查看 / 重命名 / 删除；切换时恢复该会话的人设、模型、工作目录；会话标题自动生成。
- **模型**：按会话切换，新会话沿用；失效的模型自动回落默认模型。
- **记忆**：global（个人全局）/ default（跨用户共享桶）/ persona（个人 + 当前人设）。
- **进度**：运行卡片正文上方显示 todos 与正在执行的子任务；子任务失败另发红色通知卡片；`/status` 显示运行时长、子任务累计 token、当前设置。
- **模型**：`/model` 卡片里除豆包与硅基流动外，还有 13 个经 mooya LiteLLM 的 gpt-5.6（terra / sol / luna 各档）与 deepseek-v4 模型；默认仍是豆包。
- **机器人菜单**（飞书后台按 event_key 配置）：REPO / AGENT / SESSIONS / MEMORY / MODELS 出卡片，POD 出 POD 工作台、POD_CHAT 进 POD 对话；STATUS / NEW / HELP / MEMORY_GLOBAL / MEMORY_DEFAULT / MEMORY_PERSONA 发命令；`AGENT_<NAME>` 直接切换人设。菜单依赖用户先在单聊发过一条消息。
- **单聊**：所有消息归一条连续会话、行内回复（上游原生行为）；群聊按话题分线。
