# POD 毛毯使用说明（一页版）

日常操作都在飞书单聊里完成：发 `/pod`（或点机器人菜单「POD」）打开**工作台卡片**；要上传参考图、写修改意见、问原因时，点「进入 POD 对话」和 pod-blanket 人设聊。每一步的细节、规则和排查见 `guide.md`。

## 飞书里会收到什么（精简通知，2026-10-27 起）

只有三样，其余进度不再一条条推：

- **每小时一张「POD 待办」**（有待办才发，09:00–21:00；整点的状态总结那个钟头不重复发）：**待挑选**（每个任务几张图等你挑、还在不在出，带候选表链接）、**待下载**（打好、还没标已下载的交付包，带下载链接和「B0xx 已下载」按钮）、**套图等人工**（mooya 那边停着等人处理的款）。
- **每天 10:00 / 15:00 / 21:00 一张「POD 状态总结」**：待你处理（同上）、待生成 / 进行中（每个任务出图到第几个方向、还要出约几张，拆解 / 策划中的，在 mooya 出的套图）、今日已完成（新任务、出图张数、选款选中 / 没选、套图出完、交付包、归档）、异常（暂停、积压快满、mooya 出错、要对账的调用；有才写）。
- **你让它做的事做完回一行**：传图拆解、继续裂变 / 换一批 / 修订、重新提取图案、重写描述、修改某张图、选款完成、先出套图，例如「拆解完成｜S16 名字：54 个方向、约 78 张图，开始出图」（小变化出完后程序自动接的二次大变化不单独回）。要你接着处理或出错卡住时发两行（红卡写出了什么错、该怎么办）。

出图一轮结束、套图出完、套图等人工、任务已归档、巡检提醒这些不再单独发卡片，都写进状态总结或待办。随时想看：在 POD 对话里问「现在有什么待办」「今天怎么样」，或点工作台「日报」（就是状态总结）。想改节奏（提醒间隔、时段、提醒哪几类、总结几点发）或换回原来的样式，见下面的配置。

## 后台在什么时候自己动

- **后台任务**：拆解、策划、出图、系列修订都在后台跑；你发起的做完回一行，失败发两行红卡（写出了什么错、该怎么办）；出图本身不发卡，进度在状态总结里。
- **候选表最上面的几行**：「▶ 选款完成」在那一行的「选中」打勾，几秒内后台处理整张表（那一行的「备注」先写「…中」，做完写结果、勾自动取消，再勾一次就再处理一次；2026-10-30 起随时能点，「▶ 选中的先出套图」那一行删了）；交付包行打勾当场标已下载。事件没送到（比如网关刚重启）时，下一次巡检（约 10 分钟）接上。验收会扣掉这个任务待审积压里的选款，被积压挡住的出图当场接着出。
- **「选中的款」的「下载确认」**（2026-10-27 起）：下完一款的套图在那一行打勾，几秒内这一行沉到表底；表从上到下是待下载（新出完的在最上面）→ 还不能下（在出、等人工、没出成）→ 已下载。套图没出完的款勾了会被取消；重出、在 mooya 里重生过图，勾自动取消、回到上面。一个批次的款都勾完，这个批次的交付包自动标已下载（可能当场归档）；反过来点了「B0xx 已下载」，包里的款自动打勾沉底。取消勾由巡检（约 10 分钟）回读。
- **套图**：勾店铺的犹豫期过了、或选款完成后自动交给 mooya，后台每 30 秒查一次进度，每一轮有变化就马上写进选款表和候选表（表顶的套图行）、出完的马上接着准备上架，出完拉图、打包；一个批次没有在出的款了就打这个批次的交付包（停在 mooya 等人工的款不挡，出完再补进去重打）；网关重启打断了，下一次巡检接着查。mooya 那边停在要人看的一步（比如白底图没过门控）时显示「等人工」，并出现在每小时「POD 待办」的「套图等人工」里；有人在 mooya 网页的图案管线里处理完，这边自动接着拉。停着的不占同时出图的名额，后面的款照常出。
- **Temu 上架**（开着 `temu.enabled` 时）：套图出完、定了店铺的款，后台自动准备上架图和标题；你勾「确认上架」几秒内开始建箱（套图还没出完也可以先勾，出完自动接着上）；发布结果每 5 分钟查一次，巡检兜底。「确认上架」取消勾：还没开始建箱的就不上了，已经在上的勾会被写回去。
- **全自动上架**（开着 `temu.auto` 的店，2026-10-30 起先开 3店，现在 1店–4店都开着）：在候选表勾这家店的列就是「选中 + 上这家店」，**整条流水线不用再点任何东西**：勾完 5 分钟内可以取消（撤销，犹豫期里点「选款完成」就当场定），之后程序定为选中、领货号、出套图、准备上架图和标题、替你勾「确认上架」、建箱、写品牌 MIANDUDU、发布，查到已发布就记进「已上架的款」。想停一款：在「选中的款」取消「确认上架」（暂停，再勾接着上），或在 POD 对话里说「IMG00325 先别上」。mooya 缺图自动补、暂停太久自动接着跑、没出成重出一次；白底图两轮质检都没过时用分最高的那张接着出，「上架备注」会写一句提醒你回头看。走到哪一步看「选中的款」的「当前环节」「环节开始」；卡住、没上成的进每小时「POD 待办」的「上架要你看」，后台出错发红卡。
- **改上架标题**：在「选中的款」或「已上架的款」直接改「上架标题」，约 10 分钟内程序读到、按 Temu 标题规则复核：合规的同步到店铺（还没建箱的建箱时用，在采集箱里的存回妙手，已上架的走 Temu 官方接口，接口还没接上时提醒你去 Temu 后台改），不合规的不用、原因写在「标题同步」，两张表跟着写成最新的那一版。程序写的列（店铺、货号、上架状态、上架备注、当前环节…）手改会被改回；你在表里改的每一格（旧值、新值、谁、什么时候）都记在业务库里。
- **选中的方向**：确认后一直出到全部出完，不用开连续运行；每轮最多 9 分钟，一轮结束马上接下一轮（中间先做你在选款里要求的修改），出好的图进待办「待挑选」。中途被打断（比如网关重启）时，下一次巡检会接上。
- **定时巡检**：网关每分钟检查一次，到了巡检间隔（默认 10 分钟）就巡检一轮：
  - 选中方向的出图断了就接上（不看连续运行窗口）；
  - 其他排队的任务（比如改版前的旧批次）只有开了**连续运行**（工作台「开启连续运行」，默认 24 小时窗口）时才会自动出图，没开就点「开始出图」；
  - 异常不单独发卡，写进状态总结的「异常」；
  - 每天 10:00 / 15:00 / 21:00 发状态总结（取代原来 21:00 的日报），有待办时 09:00–21:00 每小时提醒一次。

## 配置（数据目录里的 `podflow.yaml`，只能你自己改）

- `schedule.enabled` / `tick_interval_minutes` / `daily_report_at` / `digest_at`：定时巡检开关、间隔、日报时刻（旧样式用）、状态总结时刻（精简通知用，默认 10:00 / 15:00 / 21:00）。
- `trial.duration_hours`：连续运行窗口时长。
- `plan.small_count`：每轮小变化几个（默认 12，线上 30）；`plan.small_swap_ratio`：小变化里换主体的比例（默认 0 = 不分组，线上 0.8）；`plan.big_count`：每轮大变化几个（默认 8，线上 24），其中 `plan.big_single_count`（默认 4，线上 12）个是单字段大改、其余是三处组合；`plan.big_single_repeat`：同一个大改字段一轮最多几次（默认 1，线上 2）；`plan.big_single_quota` / `plan.combo_quota` / `plan.derived.quota`：单字段大改 / 三处组合 / 二次大变化里动态字段（`dynamic`：动作姿态、朝向视线、距离互动、承托依附、陪衬角色）和换画法（`technique`）各占几成（默认 0 = 随机挑，线上 0.34 / 0.34、0.5 / 0.25、0.25 / 0.4；换画法的方向由程序各分一种不重复的画法大类）；`plan.derived.*`：二次大变化（`enabled` 默认关、线上开，`count` 每批最多几个，默认 8、线上 16，`per_parent` 每个小变化最多当几次底图，默认 1）；`plan.unit`：`pairs`（默认，按「可改的主体 × 字段」挑，一处 = 一个主体上的一个字段）/ `fields`（应急回退成按字段挑）；`plan.combo_layout_fields`：以前被判成构图不动时改不了的字段（动作姿态、距离互动、陪衬角色、头身比例）也进大变化——三处组合全收，单字段大改只收其中的动态字段，可以连带调整布局（默认开）；`plan.slots_per_call`：每次 P05 写几个槽位（默认 4）；`plan.concurrency`：策划时同时跑几组（默认 4）；`batch.auto_plan_after_analyze`：拆解 / 修订后自动策划（默认开）；`batch.auto_confirm_directions`：策划完把方向全部自动确认、直接出图，不等人挑（默认关，线上 2026-10-22 起开）。可变字段少的图凑不满时少出几个，不凑数。
- `pattern_extract.*`：参考图 2D 化（S01P）的开关、模型顺序（默认 2.5-flare → 2.5-sunburst，线上 2026-10-27 起只用 sunburst）、输入图大小；关掉就用原图。
- `task_name.enabled`：拆解时给任务起短名字（默认开）；关掉后任务只显示编号。
- `describe.enabled`：拆解后写画面描述（默认开）；关掉后策划和出图指令按拆解拼的简版写。
- `image_generation.small_change_modes`：小变化的出图方式（默认只做图生图，文生图保不住原构图）。
- `review.sheet_font`：选款拼图的中文字体（线上用 mooya 的 Noto Sans SC）；不填时拼图只写 ASCII。
- `table.*`：选款表（飞书多维表格）开关、表名、协作者、原图下载链接有效天数（默认 90 天，剩 15 天时续签）；`table.views`：候选表四个视图（表格「全部」、画册「全部画册」「已选中」「待选」，链接打开「待选」）、按「排序」列排（按钮和待下载的交付包在「全部」最上面）、表名写【已选N款】【选款完成】【有新图】，「选中的款」默认看「待上架」（默认开）；`table.control_row`：候选表最上面的按钮行、交付包行、套图行（默认开）；`table.reserve_rows`：方向一确认就按出图张数预留「未生成」的行（默认开）；`table.download_confirm`：「选中的款」的「下载确认」、按「排序」排（待下载在上、已下载沉底），和交付包的已下载打通（默认开）；`table.template`：新候选表从模板表复制，画册的封面效果等只能在飞书里设的跟着走（默认开）；`table.weekly`：每周选款表（知识库根目录的模板表格锁着、每周复制一本、每天一个文件夹，默认关，线上 2026-10-29 起开），`table.weekly_since` 之前上传的任务留在旧表格。
- `shelf.*`：任务归档开关、自动归档（默认关，手动归档验证过再开）、候选表挪进去的文件夹名；`listing.*`：上架状态三列开关、多久回读一次。
- `mooya.*` / `scenes.*`：套图接哪个 mooya（地址、预设）；套图开关、选款完成后自动出、同时几款、多久查一次进度；`scenes.batch_packages`：每个批次打交付包（默认开）；`scenes.auto_heal` / `auto_retry_failed` / `auto_resume_minutes`：定了店铺的款套图自愈（缺图补、没出成重出 1 次、暂停 120 分钟后接着跑）。
- `temu.engine`：上架引擎（2026-10-30 起统一到 mooya）：`local` = 本机直连妙手（旧）、`mooya` = 确认上架的交给 mooya 上（标题、建箱、品牌、发布都在 mooya，这里只跟进、写表）；`temu.listed.source`：「已上架的款」的底账 `local`（只有这里上的款）/ `mooya`（四家店统一读 mooya，含 1店 / 2店，人填的列和改的标题写回 mooya），`temu.listed.clients` 拉哪几个 mooya 客户端；`temu.listed.crafted`：精作款周表格（`enabled`、`clients` 缺省 `[ai_temu]`：这几个客户端的款不进「已上架的款」，按上架日期进「精作款」周表格每天那张表；模板锁上之前不写；按客户端分，这条流水线自己上到 1店 / 2店的款照样进「已上架的款」）。
- `temu.*`：上架开关、店铺、发布方式；`temu.auto.*`：全自动的店（`stores`）、犹豫期（`tick_grace_minutes`，默认 5 分钟）、程序替你确认 / 自动发布；`temu.link_resave_days` / `brand_recheck_hours` / `alert_stuck_hours` / `alert_failures`：采集箱里放久了重签图片链接、品牌慢速复查、卡多久进待办、出错发红卡。`temu_open.*`：Temu 官方 Partner 接口（已上架的款改标题、回读商品 ID 和审核状态，要先建应用、店铺授权）。`table.cells_*`：多久整张读一次「选中的款」里人改的格子。
- `batch.workers` / `batch.image_concurrency` / `batch.llm_concurrency`：出图 worker 同时推进几个方向、所有工位共用几个生图名额和 LLM 名额（2026-10-26 起线上 8 / 8 / 3，2026-10-27 起 12 / 8 / 6）；`batch.queue_order`：修改优先、按任务轮流（fair）或先来先到（fifo）。
- `batch.review_backlog_limit`：待审积压上限（超过就停新出图）。
- `notify.feishu`：通知发到哪个单聊；`notify.style`：`brief`（精简：只发待办提醒、状态总结、你发起的事的一行回执和出错红卡，线上 2026-10-27 起）/ `full`（原来的样式，每个后台任务、套图、归档、巡检都发卡片，每天一张日报）；`notify.todo.*`：待办提醒的间隔（默认 60 分钟，0 = 只在状态总结里列）、时段（默认 09:00–21:00）、提醒哪几类（待挑选 / 待下载 / 套图等人工 / 上架要你看）、和上次一样要不要再发。
- `database` / `storage`：业务库在 Mooya 的 Postgres（库 `pod_blanket`），素材以 Mooya 的 OSS 为准（`pod-blanket/` 前缀），本机只做缓存，详见 `guide.md` §10.3。
- 预算与单价也在这里；人设和工作台都不能改。

## 常见情况

- 点了按钮：卡片先提示「正在……」，几秒后原地刷新。出错会换成红色卡片，点「重新打开工作台」即可。
- 提示「没有开始：……正在策划 / 还有一批方向待挑选 / 已经有 worker 在出图」：等它做完回的那一行，或先把待挑选的那批挑完，不用重复点。
- 方向现在自动全部确认；还在待挑选的批次（自动确认没成功、或开关打开前策划的）可以在 POD 对话里挑：「B003 选 1、3、5」「B003 都不要，换一批」「讲讲 B003 的方向」「F01 做过哪些方向」「F01 再出一轮，往海洋动物方向」；问「现在各个任务到哪一步了」人设会用 `podctl tasks` 回答。
- 提示「这个系列是按旧字段字典拆的，先按新字段重新拆解」：2026-10-16 字段梳理之前拆的系列，在 POD 对话里说「S01 按新字段重新拆解」（只重跑拆解、假设和系列规则，做过的方向接着算，完成后自动策划；会花一轮拆解加策划的调用）。
- 任务名字不准：在 POD 对话里说「S01 改名叫小熊野餐」（日期不变），或「S01 重新起个名字」让模型再看一次图；候选表表名一两分钟内跟着改。
- 卡片和对话里的编号后面都带名字：任务「S01 森林三伙伴水彩 1020」，批次「S01 森林三伙伴水彩 1020 · B008」，图片「IMG00123_三伙伴开怀大笑」（和候选表「素材」列同名）。说编号就能操作，比如「IMG00123 重新出套图」。
- 想知道模型怎么理解这张图：在 POD 对话里说「S01 的画面描述给我看看」；认错了就说「S01 画面描述里左边那只是小鹿」，只重写描述，之后新写的出图指令照新描述。
- 某个方向的图和原图脱钩、背景和主体画风打架：在 POD 对话里说「<方向标题>按新规则重出」，人设先告诉你要作废几张图，你同意后旧图撤出选款，按画面描述和画风规则重新写指令、重新出图（再花一轮出图的费用；已选中的款不能作废）。
- 任务列表里某个任务写「等你开始出图」：那是改版前的旧批次，不会自己接着出，点「开始出图」（或开连续运行）。
- 套图写「没出成」：任务列表点「出套图」重出（只重出没出成的）；已经出完的想重出，在 POD 对话里说「重出 IMG000xx 的套图」，会再花一套出图的费用。
