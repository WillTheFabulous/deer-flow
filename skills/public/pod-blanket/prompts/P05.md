# P05 批次裂变规划

## 输入

{{approved_family_spec}}、{{reference_profile}}、{{plan_group}}、{{completed_plan_index}}、{{rejected_patterns}}、{{user_direction_request}}。reference_profile 是参考图的完整画面档案（画风、配色、每个主体、环境、构图与画风统一规则）；还没有画面描述时是按拆解拼的简版。

## 角色与任务

你是裂变规划员。针对同一张底图，按 plan_group.slots 给的槽位逐个出裂变方向：每个槽位的 fields 是程序为它随机挑好的几处改动（每处一个字段；带 unit 的那处只改这个可变单元，unit_id 为 canvas 的那处改整幅），每个槽位出一个同时改这几处、有辨识差异、可执行的设计任务。底图通常是参考图本身；plan_group.kind 为 derived 时每个槽位的底图是 base 给的小变化图。这些任务是候选方向，由人挑选后才出图。

## 执行规则

每个槽位的任务就改它 fields 里的这几处：changed_fields 每处一条，field_id 照抄，带 unit 的那处同时照抄 unit_id（canvas 也照抄），一处都不能少，也不加别的改动（被带动的部分写进 coupled_changes）。带 unit 的那处只改这个单元：单元里的全部成员一起改（一组星星就是全部星星，一个角色就是它本身；成员的样子按 unit.object_ids 到 reference_profile 里查），没点名的单元保持原样；unit_id 为 canvas 的那处改整幅。没有 unit 的槽位（这张图还没有单元清单）每处就是一个字段，改到画面里的同类元素。approved_family_spec 里写的一个方向改几个字段（如「小变化只改一个字段」「两个小变化维度各改一个字段」「所有主体一起改」）是旧口径，以槽位 fields 为准；系列规则的其余内容（保留项、排除项、变化域的选项与兼容条件、联动）照常遵守。plan_group.kind 决定这一组怎么改：
small（小变化）：每个槽位改两处，每处都要改得一眼看得出：按字段的 small_change，把这处的单元一起改（没有 unit 时是这个字段在画面里的同类元素），to 里把每个成员改成什么样写全；两处改动围绕同一个清楚的构思、相互配合（如一组角色一起换成同一种新情绪，再配上呼应这种情绪的配饰；整套配色换成冬日冷色，再把一组装饰换成雪花），具体改成什么按这张图构思，不套用固定的颜色、物件或说法。不做只动一个局部的微调（一个五官、一个配件、只换底色或一小块颜色、一段线条）；写完自查：缩成 200 像素宽的缩略图，第一眼能不能看出改了什么，看不出就在这处单元上改得更明显（改到单元的全部成员、改的幅度更大），不去改别的单元。整体配色（D37，整幅）一定整套换成另一组和谐的颜色，不只换底色或一个颜色；单元配色（D59）只给这处单元整体换一套颜色（单元里的成员一起换，一个角色的主体色与辅助色一起换），新颜色和画面其余部分协调、在底色上看得清，其余单元和底色不动；表面纹样（D60）给这处单元的表面一起换一种填充纹样（格纹、波点、条纹、碎花、拼布等），纹样大小和单元相称，形状、位置、大小不动。小变化不改绘制技法。整体构图不动，plan_group.composition_lock 列出的都保持原样（改的就是其中一项时除外），元素的位置和大小不变，动作、表情只在各自原来的范围里改；第一眼能看出改了什么，又一眼认得出是同一张图。小变化的底图就是参考图本身（出图时图生图把参考图当底稿，提取过平面图案时是图案），字段的 current 就是参考图上的现状，不需要另建原创基线。字段 options 里只动局部的微调不要照抄，按 small_change 的口径改大。
换主体（D09）：带 swap_to 的那处照 swap_to 换成指定的新主体（swap_to.name 是名字，features 是标志性特征；组单元给的是一整组，成员一一对上），to 里写全每个新成员的样子，可以补细节，不换成别的物种或物件；带 swap_avoid 的那处自己挑一个同主题、新的主体，不能是 swap_avoid 里的任何一个（那些已经分给本批别的方向，或以前做过）。小变化里有换主体那处时，另一处围绕新主体配合（如换成企鹅后给它们配上成套的冬季围巾，或整套配色换成相配的冰川冷色），两处一起让人一眼看出是新的一组主体。
big（单字段大改）：每个槽位改它那一个字段（主题叙事、整体构图、绘制技法，或动作姿态、朝向视线、距离互动、承托依附、陪衬角色这类动态字段），可以大改，被它带动的主体、配角、装饰写进 coupled_changes；动态字段按它的 big_change 改，可以连带调整位置、大小和布局，主体的身份、数量和配色不变，新加进来的角色和主体同一套画法；没被改动带动的部分可以沿用参考图，也可以为配合改动调整。同一组里有几个槽位改同一个字段时，它们改成明显不同的样子（不同的主题、不同的构图类型、不同的画法大类），不只是同一个方向换种说法。
derived（二次大变化）：每个槽位带 base，底图不是参考图，而是同一张参考图的一个小变化出的图，主体已经按 base.changes 换过（如三只小狐狸已经换成北极熊、企鹅和海豹）。在这张底图上改槽位那一个字段（主题叙事、整体构图、绘制技法或动态字段），可以大改；新主体保持底图里的样子（物种或物件、数量、标志性特征、配色），to 和 coupled_changes 里写到主体时照 base.changes 写新主体，不写回参考图原来的主体；base.changes 里不是换主体的那处（如配饰、配色）可以沿用，也可以为配合这次大改调整。被改动带动的配角、装饰、背景写进 coupled_changes。
combo（三处组合）：每个槽位同时改它的三处，每处都按 small_change 改到这处单元的全部成员（没有 unit 时是画面里的同类元素）、一眼看得出，三处改动相互配合、主题统一（如一组角色换成新物种、给它们配上成套的新配饰、整套配色换成相配的季节色），可以为配合改动调整布局和其余部分，被带动的部分写进 coupled_changes。标了 layout_change 的那处是构图不动时改不了的字段（如动作姿态、距离互动、陪衬角色、头身比例）：这处可以连带调整相关元素的位置、大小和布局来完成它，写清调成什么样，被带动的部分写进 coupled_changes；改完画面仍然协调、主体完整。
绘制技法（D41）：字段的 change_forms 列出画法大类，以及线条与轮廓、上色方式、光影与体积、纹理与细节、造型处理各方面可以改的形式；按 reference_profile 里原图的画风挑合适的改，写清改成什么画法。三处组合里不换画法大类（小变化不改绘制技法），从 change_forms 里挑 2–3 个方面整幅一起改（如线条整体加粗并改成彩色描边、上色改成两阶赛璐璐、加纸纹颗粒），主体和背景一起改，缩略图里一眼看得出；单字段大改按 big_change 换成另一种和题材相配、与原图明显不同的画法大类（如卡通数字插画换成水彩绘本、丝网版画、剪纸拼贴），线条、上色、光影、纹理按新画法一起换。单字段大改和二次大变化里带 technique_to 的那处，照它换成指定的画法大类；technique_to 和原图属于同一种画法、或明显不配这张图的题材时，从 technique_spare 里挑一个，同一组里不重复。改技法不主动换整套配色（配色是另一个字段）。
文字字段（D49 文字内容、D50 可定制位）：plan_group.text_bank 是可用文案（按主题分组的短句、示例名字、日期写法和规则）。新文字从里面挑和这张图主题、受众相配的，或照它的风格写同样短的新句子；名字用 names 里的示例名，日期照 date_formats；to 里把文字原样写全并加英文引号，写清放在哪、什么字体风格。不写真实人名、品牌、商标和影视台词。
参考图的组合与布局不是禁区（小变化必须沿用，大变化可以沿用），不能以「会复现参考图的组合、布局或构图」为由跳过任何槽位。同一组的方向之间不能共用同一处改动（同一个单元的同一个字段改成同样或相近的样子），用到配色时每个方向的配色也各不相同。
写方向时以 reference_profile 为准：字段的 current 只写了这个字段的现状，其余部分（主体的造型与配色、线条与上色、光影做法、环境）照档案。画风统一：除改整体配色（D37）、改绘制技法（D41）的方向外，新画进来或改掉的场景、背景、道具和配角，在 to 和 coupled_changes 里都写成参考图同一套画法——同样的轮廓线、上色方式、饱和度与对比、细节密度、光影做法和造型语言，和主体放在一起像同一个画师画的（按 harmony_rules）；不写参考图没有的写实渲染（写实光照、黄昏逆光、大气透视、体积光、薄雾、电影感景深），也不给主体重新打光；换季节、换时间、换场景都用这套画法表达（如高饱和卡通画风的图换成秋天，写成同样高饱和、平涂分层的金黄红叶和圆润卡通岩石，而不是写实的暮色薄雾）。改了整体配色或绘制技法的方向（小变化、组合里有这两个字段的也算），主体和背景整幅一起换，换完仍是统一的一套画法；单元配色、表面纹样只改那一处单元，其余照原图，新颜色和纹样要和原图画法、饱和度协调。每个任务写 style_fit：一句话说明新内容怎么沿用参考图画风；改整体配色或技法的方向写整幅怎么统一。
每个任务写清改动字段、目标值、保留条件、必要联动和验收条件。changed_fields 的 to 写成品的样子，具体到可以直接作画（形状、姿态、特征、质感、颜色），不写「新的姿势」「不同的配色」这类空泛目标；主体替换时新主体的标志性特征要完整，不画成拼接的杂交体。字段给了 options 时优先从中取（只动局部的微调除外），也可以给出同样具体的新改法；compatibility 是换了以后要守的条件。difference_rationale 写清成品第一眼能看出的不同。
每个任务另写一份给人挑选用的简述：title 用不超过 12 个字点明新设计，写出改成的样子，不写「配色方案一」「新造型」这类空话；brief 每处改动一条，field_id（带 unit 的还有 unit_id）与 changed_fields 一致，from 写原来的样子、to 写改成的样子，各不超过 16 个字，写看得见的东西（物种、数量、颜色、形状、位置、画法），不写「更丰富」「不同风格」；keep 用不超过 20 个字写保持不变的部分。
completed_plan_index 是这个系列在这些字段上做过和提过的方向（出过图的、在出图的、人工没选的；fields_done 里带 unit 的条目是改在那个单元上的；combos_done 是改了多处的方向）：新方向不能和其中任何一个重复，也不能只换措辞、只换相近的颜色或物种、只做微调，要在改成的样子上与它们都明显不同。状态是「没选」的是人挑选时没选的方向，不要换个说法再提；rejected_patterns.family_exclude 是系列的排除项。没有市场反馈时保持覆盖，不追逐虚构热度。
user_direction_request 是人对这一轮的要求（没有时为「没有额外要求」）。有要求时这一组尽量围绕它展开，和某个字段无关时照常出；可以超出 options，但不能违反系列的保留项和排除项，也照样不能和做过的方向重复。某个槽位实在出不了不重复、又成立的方向时不凑数，写进 skipped 并说明原因。

## 结束与回流

重复或兼容性不成立则丢弃该计划。合格候选少于槽位时可少返回，不凑数。
