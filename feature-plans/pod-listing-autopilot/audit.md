# 盘点：飞书表落库、单图流水线状态、人改值（2026-10-29 晚，改动前）

只读核对线上 `skills/public/pod-blanket`（10-29 21:13 的版本）。下文 `podflow/` 指 `skills/public/pod-blanket/scripts/podflow/`。

## 一、勾店铺到上架，要人做的事

- 没选的新图：勾店铺列只在点按钮行（▶ 选中的先出套图 / ▶ 选款完成）时读（`candidates._read_picks` / `dispatch` / `accept`）。
  已选中的款勾店铺当场生效（`candidate_stores.apply_ticks`，10-29 21:13 上线）。
- 「确认上架」：只有人勾或对话里说（`temu.confirm`）；线上 `temu.publish: box`，要人在妙手点发布。
- 出状况才要人：
  - mooya 白底图两轮质检都没过：停在 `WAITING_CONFIRM`（等人工）；熔断：`PAUSED`。
  - 套图缺图（`partial`）：过不了 10 张图位校验，一直等；没出成的套图不自动重出。
  - 货号领号失败满 8 次（含 mooya 抖动）就不领了，还会改用 IMG 编号交给 mooya（交付包名和货号对不上）。
  - 品牌写失败满 6 次就停；定制款不自动上；妙手业务错误记没上成。

## 二、飞书表的列与落库

### 进库的
- 勾选类：选中、店铺勾（只在点按钮 / 已选中款的事件时读）、下载确认、确认上架、交付包行的勾。
- 没选原因：只记判了「不要」的行（`selection_reasons`）。
- 「选中的款」上架状态 / 上架日期 / 上架备注（`listing_marks`，覆盖写）。
- 「已上架的款」8 个人填列（`listed_products`，覆盖写）。
- 勾「确认上架」那一刻复核通过的人改标题（`listing_titles`，覆盖写）。

### 只在飞书里的
- 「选中的款」「候选表」的「备注」、人自己加的列（下载情况、使用情况…）。
- 没走「确认上架」的标题改动、复核没过的标题原文。
- 选款定了以后再改的「选中」、取消的店铺勾。

### 进库了但没有历史
- 回读值直接覆盖：销量 / 销售额 / Temu 状态没有时间序列；旧标题被盖掉就没了；上架日期、上架备注改了不留痕。
- `events` 表只有 `(ts, scope, event, payload)`：没有旧值 / 新值 / 操作人；scope 混着 IMG、任务、套图、批次、"temu"。
- 套图（`scenes._update`）和上架（`temu._update`）的中间状态迁移不记事件；卡点原因现算，不记从什么时候开始卡。

### 程序覆盖人改的值
- 「选中的款」删行（不再选中）、`table init --reset`、清理命令：人填的备注、人加的列一起没了。
- 预留行补图：清空选中、店铺勾、备注；交付包行 / 套图行整行重写或删掉。
- 「已上架的款」的程序列（货号、店铺、上架标题、妙手 ID）被改了会改回，人改的值不留。

## 三、单图流水线状态

- 状态分散在约 20 张表；没有一处能看到单款时间线（`podctl asset` 只给图片那一行）。
- 表上看不到：mooya 任务号与当前步骤、妙手 ID（只混在备注里）、图片链接到期时间、品牌重试次数、等人工 / 卡住从什么时候开始。
- 「已上架」只等于妙手采集箱 published，之后不查 Temu 侧（审核、驳回、在售、商品 ID、销量）。
- 回读 bug：上架状态「上架中」「上架失败」读回来记成「待上架」（`listing.read_cells`）。
- 关联缺：交 mooya 时实际用的包名没存；Temu goodsId / SKU 没有；发现已发布时妙手列表那一条没留。

## 四、标题改动

- 程序只在勾「确认上架」那一刻读一次「上架标题」；建箱后、发布后改的都到不了妙手。
- 妙手开放平台的「在线产品管理」只有 Shopee（Apifox 文档 llms.txt 2026-10-29 核过），Temu 半托只有采集箱接口：
  已发布的商品改不了。Temu 官方 Partner 平台有商品编辑接口（`bg.local.goods.partial.update`，提交后进 Temu 审核），
  要店铺在跨境卖家中心「系统管理 → 授权管理」授权给应用。

## 五、列的归属（改动后照这个写表头说明）

- **程序列**：素材、缩略图、方向…、货号、店铺、套图状态、当前环节、环节开始、妙手 ID、标题同步。人改了记进
  `table_cell_log`（outcome reverted），下次同步改回。
- **人填列**：备注、没选原因、人自己加的列、「已上架的款」的人填列（接上 Temu 接口之前）。程序只读、落库、不覆盖。
- **指令列**：选中、店铺勾、确认上架、下载确认、上架标题。人填的值就是要程序做的事；程序做完在状态列写结果，
  做不了写原因，不改回人填的值。
- 同一个值在两张表（上架标题在「选中的款」和「已上架的款」）：以最近一次人改为准，另一张跟着写。
