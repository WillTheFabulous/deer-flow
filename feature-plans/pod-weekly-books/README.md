# POD 毛毯每周选款表 + 锁住的模板（pod-weekly-books）

[Last Updated: 2026-11-02]

## 目标

- 知识库 Deerflow 根目录专门放一本模板表格，锁住修改权限，选款表的样子（「看图」封面效果等只能在飞书里设的）都在它里面设一次。
- 以周为单位出新的选款表：每周一本，周表格里每天一个文件夹，每个文件夹有当天的候选表、当天的「选中的款」和单独的「已归档」子文件夹。
- 本周（10-26 起）的任务搬进本周的新表格；之前的留在旧表格照常用。

## 结构

- 「POD 选款表模板（勿改）」：三张模板表「选中的款模板」「候选表模板」「已上架的款模板」，没有记录。开着高级权限，「编辑者」角色三张表只读；可管理的人（用户和程序）照样能改。
- 「POD 选款表 W44（10.26–11.01）」：一周一本（周一到周日），这周第一次要建表时从模板整本复制（知识库节点复制）。
  - 「模板」文件夹：带过来的三张模板表；这周的新表从它们复制。
  - 「10-26 周一」文件夹：那天上传的任务的候选表、「10-26 选中的款」、「10-26 已归档」子文件夹；那天第一次要建表时才建。
  - 「已上架的款」：每本一张，按上架日期归周。
- 「POD 毛毯选款表」（旧）：10-25 及以前上传的任务，什么都不变。

## 规则（用户 2026-10-29 定）

- 任务归属看上传日期（Asia/Shanghai）：候选表、选中的款都进那天的文件夹，以后继续裂变、补选也还在那天（`day_rule = upload_day`）。
- 本周搬：10-26 起上传的 S16–S27 搬进 W44；更早的留在旧表格（`old_data = this_week`）。
- 搬完核对无误后删掉旧表格里这 11 张候选表和「选中的款」里的 76 行（`old_tables = delete`）。
- 「已上架的款」每本周表格一张，只放这周上架的（`listed = weekly`）。
- 模板由程序锁：用户在开放平台开 `base:app:read / update`、`base:role:read / update`、`wiki:node:create` 并发布（`template_lock = grant_scopes`）。
- 人在旧「选中的款」里自己加的「使用情况」「下载情况」不进新表（`cols = drop`；本周 76 行这两列全空，值留在 JSON 备份里；下载情况由程序的「下载确认」管）。

## 实现要点

- `podflow/books.py`：命名与归属（`seed_places`，第一次用到时定、之后不变）、模板表格（建 / 锁）、周表格（复制 / 关掉复制件带过来的高级权限 / 模板表挪进「模板」文件夹 / 订阅事件）、天（文件夹 + 嵌套的已归档 + 当天的「选中的款」）、`status`；业务库表 `table_books` / `table_days` / `seed_places` / `table_places` / `listed_books`。
- `podflow/table_registry.py`：程序在周表格里建的表登记 app_token，候选表各接口按 table_id 拼路径；按份同步「选中的款」时的 contextvar 过滤（`mine`）。
- `feishu_table.sync` 按份同步「选中的款」（旧表格一份 + 每天一份）；`candidates._ensure_table` 归到某天时从那本周表格的候选表模板复制进那天的文件夹；`_sync_shelf` 挪进 / 挪回那天的文件夹；`control_event` 按 table_id 认是哪一份「选中的款」、哪本表格的候选表；`downloads` / `listing` / `temu` / `scenes` 按份读写；`listed_table` 按上架周写进那本周表格。
- `podflow/week_migration.py`（`podctl maintenance migrate-week --week 2026-W44 [--dry-run] [--keep-columns]`）：读回人填的 → JSON 备份 → 建周表格和那几天 → 业务库里指向旧行的记录清掉、归属改到那天 → 新候选表照业务库重写（含已定的行和预留行）→ 同步 → 搬人填的格子 → 逐格核对 → 删旧表、旧行。持有迁移租约，巡检回读和记录变更事件这期间先不处理；每步记在 meta `books.migrate.<周>`，重跑接着做。重写的候选表行 50 行一批建；一批报错重试一次；重跑时重建过的任务也再过一遍补缺的行；核对前删掉新候选表里业务库不认识的行（报错的那一批飞书那边可能已经建了）。
- 开关 `table.weekly`（默认关，搬完再开）、`table.weekly_since`（缺省 2026-10-26）；`podctl table books [--lock]`；`table galleries` 列出模板表格、每天的「选中的款」、每张候选表和「已上架的款」的「看图」。

## 精作款周表格（2026-10-31，`temu.listed.crafted`，用户定）

mooya 上做的款（1店 / 2店：mooya 底账里客户端 `ai_temu` 的行）不进「已上架的款」，单独放「精作款」周表格；「已上架的款」只放这条流水线上的款（10-31 时只有 3店 / 4店；2026-11-02 起 1店 / 2店的自动化款 FLRP / JUHP 也在这里，有 1店 / 2店视图——按 mooya 客户端分，不按店铺）。

- 结构：知识库根目录一个「精作款」节点（文档，只当目录），下面放锁住的「精作款模板（勿改）」（一张「精作款模板」：列照「已上架的款」，视图 全部 / 1店 / 2店 / 看图）和每周一本「精作款 W44（10.26–11.01）」（整本复制，模板表挪进「模板」文件夹）；周表格里每天一张表「10-26 周一」（从「精作款模板」复制，挪到根目录）。
- 规则：按上架日期（Asia/Shanghai）登记到那一天，定了不变（`crafted_places`）；历史全部按周、按天进各自那一周（W30–W44，约 60 天）；人填的列、改标题和「已上架的款」一样写回 mooya。
- 模板要人在「看图」里设封面效果（接口改不了）再 `podctl temu listed crafted lock`；锁上之前精作款的新行哪里都不写。
- 迁移 `podctl temu listed crafted migrate [--dry-run]`：删精作款在「已上架的款」里的行（500 一批），旧表格那张只剩精作款（人也没加行）时整张删，周表格那张删 1店 / 2店视图；按日期先后建好各周、各天；之后 `temu listed sync --batch N` 写行。还在「已上架的款」里没迁的行照旧在那边，不会写两份。
- 代码：`podflow/crafted.py`；`listed_table.place` 给 `crafted:<day>`，`_meta` / `_places` / 写行 / 回读 / 视图 / 店铺选项同一套代码（精作款的表只有 1店 / 2店）；业务库表 `crafted_books` / `crafted_days` / `crafted_places`；`books.lock_tables` 两边共用。

## 线上实测结论（2026-10-29）

- 知识库节点整本复制：视图 id 不变、封面效果跟着走；高级权限也跟着复制（复制件要关掉）；复制是异步的，复制完之前接口报 1254036「Bitable is copying」，要等。
- 块接口 `parent_id` 能在文件夹里建文件夹；新建的多维表格自带 Dashboard / Workflow 块，复制时一起带过来（不碍事）。
- 飞书多维表格单条写（新增 / 删除一行）一次 3–4 秒（旧表格、周表格都一样），`batch_create` 二十行也约 3 秒：成批重写要用批量接口。偶发 1255002 RpcError。
- Base v3 角色接口：返回的 `data` 是 JSON 字符串，列表里每个角色也是 JSON 字符串；系统角色 Editor / Reader 可以改。改角色是增量合并，`role_name` / `role_type` / `base_rule_map` 必带，表权限不是 `no_perm` 时 `view_rule` / `record_rule` / `field_rule` 要给全，少了报 code 1（没有 msg）。
